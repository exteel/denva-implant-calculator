# DENVA AI — Калькулятор імплантації v3 (ТЗ 3.3): архітектура

Джерела: `docs/TZ_v3.3_DENVA_AI.txt`, шаблон клініки `public/templates/DENVA_shablon_tsin_kliniki.xlsx`.
Рішення власника (17.10.2026): SEO-сторінки поки на GitHub Pages (домен — пізніше, тож усі міста
стартують у draft/noindex); для 7–14 зубів питаємо лише стан.

Ця редакція **замінює** схему екранів і формул v2. Інфраструктура v2 (Supabase, RLS, черга
перерахунку, snapshots, audit log, Telegram, адмінка, GitHub Pages) лишається.

## 1. Модель цін (ТЗ §2–3)

**Базовий орієнтир** для (місто, service_code, tier): ручна ціна міста → ручна середня ціна області →
ручна середня ціна України (нова таблиця `country_manual_prices`).

**Публікація** (заміна `publish_price`):

| Локальних перевірених клінік (один голос, філії з однаковим прайсом = 1) | Значення | `source_type` |
|---|---|---|
| `manual_override` увімкнено | значення адміністратора + причина | `manual_override` |
| ≥ 3 | медіана локальних | `aggregate` |
| 2 | ⅔ · медіана локальних + ⅓ · baseline | `hybrid` |
| 1 | ⅓ · локальна + ⅔ · baseline | `hybrid` |
| 0, baseline міста | baseline | `manual_baseline` |
| 0, baseline області | baseline | `regional_fallback` |
| 0, baseline України | baseline | `national_fallback` |
| немає нічого | рядка немає → «даних поки недостатньо» | — |

Якщо в hybrid немає жодного baseline, публікується медіана локальних (позначка `hybrid`, вага baseline 0).
Snapshot зберігає: локальну вибірку, медіану, baseline (значення + scope), ваги, формулу.
Публічна ціна віддає: `value, currency, source_type, source_scope, local_clinic_count, baseline_scope,
blend_weights, calculated_at, exchange_rate`.

**Каталог** — рівно коди з шаблону (32 коди). Рівневі (`tiered`, від рівня імпланта): IMPLANT_INSTALL,
HEALING_ABUTMENT, SUPERSTRUCTURE_SET, ABUTMENT_FINAL, MULTIUNIT; від рівня коронки/конструкції:
CROWN_IMPLANT, ARCH_FINAL. Решта — `common`. Старі коди v2 деактивуються міграцією.

## 2. Розрахунок (ТЗ §4, §8) — один модуль `calculateJaw()`

`src/engine/v3/` — чистий TypeScript, детермінований, округлення лише при показі.
Той самий модуль (згенерована копія, перевірена тестом на ідентичність) працює:
- у браузері — щоб сума змінювалася миттєво;
- в Edge Function `calculate` (ТЗ §8: `city_id + upperJawInput + lowerJawInput → upperJawCalculation,
  lowerJawCalculation, overallTotal, priceMeta`) — для Dental Tender і перевірки заявок.

| Щелепа | Формула |
|---|---|
| 1 зуб | implant[it] + healing[it] + scan_jaw + superstructure[it] + crown[ct] |
| 2–6 поруч | таблиця §4.3 (2→2/2, 3→2/3, 4→2/4, 5→3/5, 6→3/6) |
| 2–6 окремо | N·(implant+healing+superstructure)[it] + N·crown[ct] + scan_jaw |
| 2–6 «не знаю» | діапазон «поруч … окремо» |
| імпланти вже є | scan_jaw + installed·superstructure[it] + teeth·crown[ct]; невідома кількість → діапазон за допустимими схемами |
| 7–14 | 4 сценарії: **Мости** = 4·(implant+healing+superstructure)[it] + scan_jaw + teeth·crown[ct]; **All-on-4/6/8** = first_stage (N·implant + N·multiunit [it] + arch_temp + scan_jaw) + arch_final[at] + repeat_scan |
| тимчасове протезування (перемикач) | + teeth·temp_crown + repeat_scan + implants·abutment_final[it] (не для All-on — там arch_temp уже є) |
| дві щелепи | overallTotal = upper.total + lower.total; у кожної щелепи своє сканування й рівні |

Ціни зберігаються в UAH (нормалізація EUR/USD за НБУ на дату snapshot); перемикач ₴/€ на результаті.

## 3. Екрани (ТЗ §5–6)

1. **Місто**: «Без реєстрації. Результат одразу після відповідей»; у результатах пошуку місто + область;
   «Не знайшли своє місто? Оберіть область»; після вибору — автоматичний перехід.
2. **«Скільки зубів потрібно замінити імплантами?»** — два бігунки 0–14 (верхня / нижня) з −/+,
   число постійно видно; не можна продовжити з двома нулями; «Не знаю точно» замінює обидва
   бігунки → одне уточнення: окремі зуби / значна частина / можливо всі / зовсім не знаю.
3. **Питання по щелепах послідовно** (спочатку верхня, потім нижня, з підписом щелепи):
   1 зуб → стан; 2–6 → розташування + стан; 7–14 → стан; «імпланти вже встановлені» →
   «Скільки імплантів уже встановлено?» (бігунок 1…кількість зубів + «Не знаю»). Щелепа з 0 пропускається.
   Стан: уже видалені / частина залишилась / лікар рекомендував видалення / імпланти вже встановлені / не знаю.
4. **Результат**: блок «Верхня щелепа», блок «Нижня щелепа», «Загальна орієнтовна вартість» (проста сума).
   Одна основна картка на Класичному рівні; у кожній щелепі незалежні перемикачі рівня імпланта
   і коронки/конструкції; компактні рядки «Мінімальний» / «Преміальний». Для 7–14: порівняння
   чотирьох бюджетів, потім вкладки Мости / All-on-4 / All-on-6 / All-on-8 (без медичної
   рекомендації). Перемикач тимчасового протезування, перемикач ₴/€, джерело цін за ТЗ §6.1
   (0 / 1–2 / 3+ клінік, місто / область / Україна), дата, «Що може знадобитися додатково» з
   міськими цінами (не в total), примітка для двох щелеп, застереження.
5. **Заявка під результатом**: основна кнопка «Отримати персональні пропозиції від перевірених
   клінік» (`intent = dental_tender`; у MVP — у Telegram), друга «Уточнити мій розрахунок»;
   payload містить upperJawCalculation, lowerJawCalculation, overallTotal.

Припущення для «Не знаю точно»: окремі → 1–3 окремі зуби (діапазон), значна частина → 10 зубів
однієї щелепи (порівняння сценаріїв), можливо всі → 14 зубів однієї щелепи, зовсім не знаю →
довідкова ціна одного зуба. Кількість можна змінити на результаті.

## 4. SEO (ТЗ §11)

- Маршрути (під basePath): `/implant-calculator/` (каталог опублікованих міст + методологія коротко),
  `/implant-calculator/{city-slug}/` (калькулятор без кроку міста + статичний HTML-блок «Середні ціни
  у місті» min/classic/premium, дата, кількість джерел, що входить, додаткові витрати, методологія,
  FAQ, рецензент), `/implant-calculator/methodology/`. `/` і `/calculator/` → канонічно на `/implant-calculator/`.
- Сторінки генеруються під час збірки з даних Supabase; щоденне перезбирання (GitHub Actions cron) +
  при кожному деплої. Ціновий блок і JSON-LD (BreadcrumbList, WebPage, FAQPage лише з видимими
  питаннями) — у статичному HTML.
- Статус міста в адмінці: draft / review / published / stale / removed. Лише published → index,
  self-canonical, sitemap.xml, каталог. Решта → noindex (removed — сторінка «місто більше не
  підтримується» з посиланням на область; 301/410 на GitHub Pages неможливі — з'являться з власним доменом).
- Контент міста (вступ, локальні FAQ, рецензент, дата перевірки) — поля в адмінці; автоматичного
  шаблонного тексту немає (ТЗ забороняє scaled content), тож без заповненого контенту місто не
  публікується.
- Стан калькулятора — лише у frontend state / localStorage; жодних індексованих URL-комбінацій.

## 5. Адмінка (ТЗ §7)

- Каталог послуг v3, ручні ціни з рівнем `common`, нова сторінка «Базові ціни України».
- Агрегати: локальна вибірка, медіана, використаний baseline (scope), ваги hybrid, опубліковане значення.
- Шаблон для клінік — **ваш файл** як є; імпорт читає саме його формат (картка клініки + таблиця
  з рядка 15, коди й рівні вже проставлені, порожні ціни пропускаються); поля «Участь у Dental
  Tender» і «Згода на публічний профіль» зберігаються в картці клініки.
- Місто: slug, статус SEO, контент сторінки.

## 6. Виконання

Паралельно 4 агенти з окремими файлами: (1) база: міграції 08+, seed, функція `calculate`, тести;
(2) рушій v3 + калькулятор; (3) адмінка; (4) SEO-сторінки, sitemap, методологія. Потім перевірка
стиків, e2e кожної гілки, деплой. Поточний сайт працює до злиття.
